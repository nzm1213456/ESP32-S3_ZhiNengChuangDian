# 基于ESP32‑S3的智能床垫

## 摘要
为解决当前传统睡眠监测设备穿戴束缚、摄像头监测存在隐私泄露问题、以及传统床垫无法动态适配人体睡姿、实时监控使用者健康状态等行业痛点，本产品设计了一款以ESP32‑S3为核心主控，搭载R60ABD1 60G毫米波雷达的AI自适应智能床垫系统。

系统依托毫米波雷达非接触式微动感知能力，无需穿戴设备即可无感采集人体心率，呼吸频率，体动幅度等睡眠体征数据；ESP32‑S3通过WiFi将原始监测数据上传至OneNET物联网云平台，平台规则引擎将过滤后的异常时序数据转发至阿里云AI服务，调用“通义千问”大模型完成睡眠周期分类，异常告警与每日睡眠健康小结等内容，输出调控指令下发至Android客户端与床垫主控。

硬件层面集成多通道压力支撑调节模块（demo中展示为舵机），结合AI睡眠分析结果实现床垫分区软硬度自适应调控：深度睡眠阶段自动降低床垫支撑硬度，减少夜间翻身扰动。系统内置声光报警单元，当雷达识别呼吸暂停、心率异常等危险体征时本地声光预警，同步推送大模型生成的专业告警至手机APP。

本方案全程无视觉采集元件，仅依靠毫米波感知人体微动，从底层规避视频图像隐私泄漏风险；ESP32‑S3自带低功耗协处理器实现7×24小时全天候待机监测，依托阿里云通义千问进行AI辅助监测，支持远程数据查看、睡眠模式自定义、历史睡眠数据回溯。

本产品拓展性强，兼顾健康监测与睡眠体感优化双重需求，面向居家健康、中老年康养、失眠人群提供轻量化、低成本、高隐私性的物联网睡眠解决方案，具备良好的民用落地与二次开发价值。

**关键词**：ESP32‑S3；60G 毫米波雷达；非接触体征监测；OneNET云平台；通义千问；智能床垫

# 第一章 设计需求分析
## 1.1 行业现有产品痛点分析
当前市场主流智能睡眠产品分为穿戴式监测设备、摄像头监护设备、高端气动智能床垫三类，三类产品均存在难以兼顾实用性、隐私性、成本的固有缺陷。

穿戴式手环、胸贴传感器存在束缚干扰问题。睡眠过程中穿戴设备易产生异物感，翻身时易脱落、移位，导致心率、呼吸数据断采，无法实现整夜连续监测；柔性电极长期贴合皮肤易引发过敏，不适用于皮肤敏感人群与老年群体。

摄像头视觉监测存在严重隐私泄露风险。家用摄像头采集人体图像、视频数据，存储、传输过程中存在数据泄露隐患，卧室属于高度私密空间，多数用户排斥卧室部署摄像设备；红外摄像头仅能识别人体轮廓，无法精准捕捉胸腔、心脏微米级微动，体征监测误差大。

市面高端智能床垫多采用气动气囊分区调节，硬件成本千元以上，普及门槛高；调节逻辑仅支持固定档位手动切换，无基于睡眠状态的自动联动机制，无法根据用户实时睡姿、睡眠深浅动态调整支撑力度；普通弹簧床垫无自动调节功能，长期单一支撑易造成腰椎悬空，加剧腰背酸痛问题。

## 1.2 用户核心使用需求分析
### 1.2.1 普通居家用户健康监测需求
当代中青年普遍存在熬夜、失眠、睡眠浅等亚健康问题，用户需要低成本设备长期记录睡眠时长、深浅睡眠分布，量化评估睡眠质量；需求设备无穿戴束缚、不影响睡眠，可通过手机直观查看AI生成的专业睡眠报告；同时希望床垫能够自动适配身形，减少夜间翻身次数，提升睡眠舒适度，且无视觉设备泄露个人隐私。

### 1.2.2 中老年群体安全监护需求
中老年人群高发睡眠呼吸暂停、夜间心率失常等病症，独居老人存在夜间突发疾病无人发现的安全隐患；家属需要远程实时查看老人睡眠体征，出现呼吸骤停、心率异常时设备本地声光报警，并推送大模型生成的清晰易懂告警文案至手机；老年用户排斥复杂穿戴设备、摄像头，要求监测方式无感、无隐私风险。

## 1.3 产品设计目标
监测层面：为解决传统接触式设备舒适度较差，视觉识别设备容易泄露个人隐私的问题，本设计采用60G毫米波雷达实现非接触无感采集，无图像采集，保护个人隐私；精准识别心率、呼吸、体动等睡眠体征，体征测量误差满足家用健康监测标准。

控制层面：为解决传统床垫无法自动调节舒适度问题，本产品依托ESP32‑S3联动多通道压力调压模块，结合AI大模型睡眠分析结果实现床垫分区支撑自适应调节，动态贴合人体脊柱曲线。

互联与AI层面：为解决传统床垫无法记录睡眠情况并自主提出建议，本产品对接OneNET物联网云平台，搭配通义千问构建低成本AI分析链路，内置多层阈值过滤大幅削减模型调用量，对睡眠质量实现低成本持续监测；开发Android客户端，支持远程查看数据、自定义睡眠模式、异常告警推送等功能。

落地层面：为解决传统床垫舒适度与成本不可兼得问题，封装精美可靠，保证床垫舒适性的同时兼顾测量准确及便于维修，合理设计节省制造成本。

# 第二章 特色与创新
## 2.1 非接触式无感体征监测架构
### 2.1.1 60G毫米波无穿戴采集方案
本系统采用R60ABD1 60G毫米波雷达作为唯一感知元件，完全摒弃手环、电极、压电薄膜等接触式传感器，实现全无感睡眠监测。雷达电磁波可穿透被褥、睡衣等非金属介质，无需人体皮肤接触即可捕捉胸腔呼吸起伏、心脏搏动产生的微米级微动信号，整夜持续采集无中断；解决传统穿戴设备脱落、皮肤过敏、束缚睡眠的痛点，适配全年龄段用户长期使用。区别于市面外置式雷达监测仪，本方案将雷达集成于床垫内部，无需额外摆放设备，一体化集成度更高，不占用卧室空间。

## 2.2 无视觉感知，全方位隐私保护机制
### 2.2.1 纯电磁波探测规避图像泄露风险
本系统全程未搭载摄像头、红外图像采集设备，仅依靠60G毫米波电磁波完成人体探测，不存在图像、视频数据采集、存储、传输环节，从底层杜绝卧室隐私泄露隐患。毫米波仅解析人体微动频率特征，不生成人体轮廓、人像等可视化信息，云端、本地仅存储心率、呼吸数值、睡眠状态标签等纯数字数据，不存在图像泄露风险，解决用户对卧室视觉监控的抵触心理，适配居家私密场景长期部署。

## 2.3 高灵敏毫米波微动信号解析技术
60G毫米波具备短波长、高距离分辨率特性，可捕捉亚毫米级人体微动，区分大幅度翻身体动、微弱胸腔呼吸、心脏搏动三类不同量级信号，信号信噪比优于24G毫米波与红外传感。ESP32‑S3内置数字滤波算法对雷达原始回波信号预处理，滤除床垫抖动、环境电磁干扰，提升心率、呼吸数据采集精度；即使用户多层被褥覆盖、侧卧蜷缩睡姿，仍可稳定解析体征数据，监测灵敏度显著优于压电、红外类传统传感器。

## 2.4 低成本云原生AI联动自适应调压创新机制
现有智能床垫AI方案多采用第三方大模型，无前置数据过滤，全量数据高频调用造成高额费用，且物联网平台与大模型跨厂商对接兼容性差。本作品创新构建OneNET阈值过滤+通义千问一体化低成本AI链路：

(1) 本地+云端双层硬规则过滤，仅异常体征、每日时序汇总数据才触发大模型调用，调用量削减95%；
(2) 选用通义千问作为核心大模型，低频调用每月仅几元，按量单价0.5元/1000 tokens，是性价比最优轻量化模型；

实现“雷达体征采集→OneNET规则过滤→通义千问AI分析→床垫分区调压”全链路自动闭环调控，AI仅负责异常告警文案生成、每日睡眠健康小结输出，轻量化算力需求匹配家用场景，兼顾智能调控与极低运维成本。

# 第三章 功能设计
## 3.1  非接触式睡眠体征监测功能
### 3.1.1 心率、呼吸实时采集模块
床垫内置R60ABD1毫米波雷达持续发射60GHz电磁波，接收人体胸腹微动反射回波，ESP32‑S3通过串口读取雷达原始信号，经处理获取心率、呼吸频率体信息，换算为每分钟心率值、呼吸频率，采样周期1秒，本地缓存5分钟短时体征数据，保障网络断连时数据不丢失。

### 3.1.2 睡眠周期自动识别与数据存储
设备将连续体征时序数据上传OneNET云端，平台本地规则完成第一层阈值过滤，仅满足异常条件的数据批量转发至通义千问，模型综合体动频次、心率波动幅度、呼吸节律综合判定清醒、浅睡眠、深睡眠、快速眼动睡眠四种状态；云端自动统计总睡眠时长、深睡占比、夜间翻身次数，存储AI生成的标准化睡眠健康报告，支持近30天历史数据回溯。

### 3.1.3 生命体征异常声光报警功能
ESP32‑S3本地实时判别体征阈值：当连续10秒未检测到呼吸（呼吸暂停）、心率持续高于120次/分钟或低于40次/分钟时，立即触发蜂鸣器本地报警；同时将异常告警数据包上传OneNET，经规则引擎转发至通义千问生成通俗易懂、具备健康提示的告警文案，回传OneNET后推送至绑定的Android APP，远程提醒用户或家属，针对中老年人夜间突发呼吸、心脏风险提供安全预警。

## 3.2 AI分区自适应支撑调节功能
### 3.2.1 睡姿动态识别与压力点位匹配
毫米波雷达可识别平躺、左侧卧、右侧卧三类主流睡姿，结合人体微动分布判定肩、背、腰、臀、腿部五大承压区域；系统内置支撑力度映射数据表，不同睡姿对应分区舵机标准转角参数，实时匹配人体脊柱生理曲线，针对腰部悬空区域自动加大支撑力度，缓解腰背劳损。

### 3.2.2 分时段床垫软硬智能调控逻辑
浅睡眠/清醒阶段：监测到用户频繁翻身，小幅交替调节分区支撑，减少身体局部压迫；

深度睡眠阶段：通义千问判定进入深睡周期后，输出调节指令下发ESP32‑S3，自动降低腰臀支撑硬度，减少身体挤压，延长深睡时长；

离床状态：雷达检测用户离床超过3分钟，舵机自动复位至标准中性档位，降低设备功耗。

同时支持APP手动自定义固定睡感档位，兼容用户个性化调节需求。

## 3.3 物联网云端与移动端交互功能
### 3.3.1 OneNET云端数据转发与阈值过滤
ESP32‑S3通过WiFi以MQTT协议接入中国移动OneNET物联网平台，设备周期性上传原始心率、呼吸、体动、设备状态数据；平台内置规则引擎配置硬过滤规则，仅满足「夜间心率、呼吸频率超出阈值、HRV指标偏低、呼吸暂停」四类异常条件的数据才转发，正常健康数据直接丢弃，大幅削减大模型无效调用；云端提供数据持久化存储、消息双向转发、设备在线状态管理能力，提供标准化HTTP转发接口对接AI大模型。

### 3.3.2 通义千问AI分析服务
OneNET批量推送的JSON格式体征数据经封装API请求调用通义千问模型，模型仅承担两类轻量化任务：异常体征场景生成健康告警推送文案；每日全量时序数据批量分析，输出标准化睡眠健康小结、睡眠阶段判定结果、床垫支撑调节参数；AI返回结果回写至OneNET平台下发主题，同步推送至Android客户端。

### 3.3.3 Android APP数据可视化与远程控制
Android客户端功能包含：实时体征曲线展示、每日AI睡眠报告可视化、历史睡眠数据图表查询、床垫支撑档位远程手动调节、异常告警弹窗（附带通义千问生成的健康提示文案）、设备WiFi配网、睡眠模式自定义设置；APP支持多设备绑定，可同时查看多张床垫监测数据，适配家庭多人使用场景。

# 第四章 系统实现
## 4.1 感知层技术
感知层负责人体睡眠体征原始数据采集，是系统数据输入源头，核心硬件为60G毫米波生命雷达，配套信号滤波电路完成微动信号降噪预处理。

### 4.1.1 毫米波雷达硬件电路设计
感知层核心器件为R60ABD1 60G毫米波雷达模块，模块标准供电5V，通过硬件UART串口与ESP32‑S3的U1串口建立通信；雷达内部集成射频发射天线、接收天线与专用信号预处理芯片，可直接输出经过初步解调的心率、呼吸原始数值，无需后端复杂信号解调。

## 4.2 传输层技术
传输层承担设备端、OneNET云平台、阿里云AI服务、Android客户端之间双向数据交互，包含本地WiFi局域网通信、MQTT物联网协议、平台数据转发链路三类核心传输技术。

### 4.2.1  WiFi双向数据传输协议配置
ESP32‑S3集成2.4G WiFi射频单元，接入家庭无线局域网，采用轻量级MQTT物联网传输协议，报文载荷体积小、通信时延低，适配低功耗嵌入式终端。设备设置30秒心跳包维持与OneNET云端长连接；上行通道周期性上传心率、呼吸、体动、设备在线状态等体征数据；下行通道接收云端AI下发的床垫分区支撑调节指令。网络断开时主控本地Flash缓存短时体征数据，网络恢复后自动断点续传，避免监测数据丢失。

### 4.2.2 OneNET设备接入与规则引擎转发链路
在OneNET物联网平台创建产品，生成对应产品ID、设备密钥三元组，完成设备身份鉴权；

ESP32‑S3嵌入式程序内置设备三元组信息，上电自动发起MQTT连接认证，建立加密通信链路；

订阅云端指令下发主题、发布设备体征上报主题，完成双向消息通道绑定；

配置云产品流转规则，编写条件过滤语句筛选异常体征数据，将过滤后JSON数据包转发至阿里云AI大模型。

## 4.3 控制层技术
控制层以ESP32‑S3为主控核心，包含嵌入式资源调度、多路舵机分区调压控制、本地声光异常报警三部分硬件与驱动逻辑，完成床垫硬件设备实时闭环控制。

### 4.3.1  ESP32‑S3主控资源调度实现
主控选用ESP32‑S3‑WROOM‑1模组，内置Xtensa LX7双核处理器、2.4G WiFi、蓝牙、大容量PSRAM与Flash存储，搭载低功耗ULP协处理器。嵌入式软件基于ESP‑IDF开发框架搭建，采用FreeRTOS多任务调度机制划分业务线程：任务1：雷达串口数据读取；任务2：PWM舵机驱动控制；任务3：MQTT云端数据上传、下行指令解析；任务4：本地体征阈值判断、声光报警触发逻辑。

### 4.3.2 分区舵机调压与声光报警执行单元
床垫支撑调节执行元件采用多路SG90微型舵机，通过PWM舵机控制通道，实现肩、腰、臀、腿多分区独立转角调节，精准控制床垫各区域软硬度；本地安全报警单元由有源蜂鸣器组成，通过主控GPIO10引脚驱动，识别呼吸暂停、心率异常时同步触发蜂鸣鸣响与灯光闪烁，实现本地实时预警。

## 4.4 软件开发技术
软件开发覆盖三大部分：阿里云AI服务开发、Android移动端APP开发、系统全业务流程联动逻辑开发，包含云函数、大模型调用、前端可视化、端云协同流程。

### 4.4.1 OneNET规则引擎阈值过滤开发
在OneNET规则引擎中配置多条件过滤语句，仅当心率、呼吸、HRV、体动指标超出健康阈值时，才将结构化JSON体征数据批量推送至阿里云AI接口；正常健康区间数据直接丢弃，从源头削减95%以上无效大模型调用，降低AI服务使用成本。统一推送数据字段包含设备ID、时间戳、心率、呼吸、HRV、体动频次，标准化字段便于后端服务解析处理。

### 4.4.2 通义千问大模型调用开发
本系统选用通义千问作为轻量化AI推理模型，为场景内高性价比方案，配套开发标准化调用逻辑，计费与调用约束规则如下：

计费规则：按量单价0.5元/1000 tokens；本项目仅执行异常告警文案生成、每日睡眠小结两类轻量化任务，家用低频调用场景每月消耗仅数元，成本可控。

调用场景限制：仅两类业务触发模型推理，无全量实时高频请求：
（1）异常体征触发：雷达识别呼吸暂停、心率超标等风险，异常时序数据请求模型生成适配中老年人群的通俗健康告警文案；
（2）每日批量汇总：每日凌晨FC拉取当日完整体征时序，批量送入模型完成睡眠阶段划分、睡眠质量评分、床垫支撑优化参数输出。
（3）调用参数优化：严格限定输入上下文长度，单次请求token消耗控制在数百级，进一步降低计费消耗；模型温度参数调低至0.3，保证输出内容标准化、稳定可解析，适配设备自动调控逻辑。

### 4.4.3  AI输出指令回传与端云联动逻辑开发
通义千问输出两类结构化数据：文本类告警/睡眠报告、数值类分区舵机调节参数；文本数据推送Android APP用于可视化展示，ESP32‑S3订阅对应主题接收参数，驱动多路舵机实时调整床垫分区支撑硬度，完成“感知‑过滤‑AI分析‑硬件执行”完整闭环链路开发。

### 4.4.4 Android客户端软件实现
基于Android Studio开发原生安卓APP，整体划分为四大功能模块：设备WiFi配网模块、实时体征数据展示模块、AI睡眠报告可视化模块、床垫远程手动控制模块；通过HTTP请求对接OneNET开放API拉取设备历史数据，内置MQTT客户端实时监听云端AI异常告警消息。界面采用折线图实时展示心率、呼吸变化曲线，柱状图统计每日睡眠时长分布，AI生成的健康小结、风险提示单独分区展示，交互逻辑简洁易懂，适配中老年用户操作习惯。

## 4.5 系统整体工作流程
用户躺卧床垫，感知层60G毫米波雷达持续采集人体胸腹微动体征原始数据；

控制层ESP32‑S3本地完成信号滤波预处理，实时判别体征阈值，触发本地声光报警；

传输层WiFi链路周期性将标准化体征数据上传OneNET云平台；

OneNET规则引擎执行硬规则过滤，仅异常数据转发至阿里云AI大模型，生成告警文案、睡眠分析结果、床垫分区调节参数，AI输出结果回传OneNET平台，分两路下发：文本信息推送Android APP，硬件调控指令下发ESP32‑S3主控；

控制层ESP32‑S3接收调节指令，驱动多路舵机分区动态调整床垫支撑力度；

Android APP实时拉取云端存储数据，展示实时睡眠曲线、AI每日健康报告、异常告警弹窗提示；

用户离床后，触发低功耗休眠，设备进入待机监测状态，等待下一次人体感知。
